## How the documentation is organised

- **Projects** describe individual sites, APIs, tools and services.
- **Guides** help readers complete tasks and include migrated documentation.
- **Reference** contains stable facts, schemas and architecture relationships.
- **Operations** contains runbooks and maintenance procedures.
- **Archive** is for retired systems and historical material.

## Where to begin

1. Browse the [repository index](/repos/), the [builds](/builds/) (labs, tools and apps) and the [GitHub Projects boards](/boards/).
2. Read the [repository ecosystem](/reference/ecosystem/).
3. Follow the [documentation authoring guide](/docs/guides/getting-started/docs-authoring/).
4. Check the [domain inventory](/reference/domains/domain-inventory/) before making infrastructure changes.

Project status and review metadata are not substitutes for a live health check.
